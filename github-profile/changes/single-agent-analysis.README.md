# single-agent-analysis

`single-agent-analysis` 是一个用于深入拆解单个 Agent 的研究型 Skill。它从可观察行为、公开材料和已有操作记录出发，梳理 Agent 的任务流程、运行机制、上下文与状态、工具约定及提示词设计，并明确区分实测事实、公开信息、研究推断与未知项。

这个项目由个人维护，不是任何被分析产品的官方实现，也不声称能够还原其未公开的后台配置。

## 适用场景

- 独立研究一个 Agent 如何接收输入、选择行动、调用工具、处理失败并完成任务。
- 为 Agent 原型设计整理可测试的 Tool 定义、状态约定和提示词草案。
- 在竞品研究中，对已经确认的单个 Agent 做技术层深挖。
- 复盘 Agent 的问题，形成包含证据、原因假设、改进建议和验证方法的诊断。

它不负责完整的产品定位、市场分析、需求排期或多 Agent 总体架构，也不会把普通功能模块或一次模型调用直接认定为 Agent。

## 主要产出

Skill 默认要求交付六组内容：

1. 真实行为记录与逻辑流程图。
2. 规划、行动选择、检查、停止和恢复等运行机制说明。
3. 上下文、状态和产物的读写约定。
4. Tool 清单及关键工具定义草案。
5. 包含七个部分的完整提示词反推草案。
6. 问题诊断、可借鉴机制及后续验证缺口。

当材料不足时，产出应保留未知项和证据限制；未经实现与测试的内容只能标为研究者重构或原型建议。

## 安装与调用

### Codex / ChatGPT Skills 目录

将仓库克隆或下载后，把整个目录放入当前环境识别的 Skills 目录。不同客户端和团队环境的目录位置可能不同，请以所用产品的 Skill 安装说明为准。安装后确认目录名为 `single-agent-analysis`，并保证 `SKILL.md` 与 `references/analysis-spec.md` 的相对路径不变。

调用示例：

```text
请用 $single-agent-analysis 拆解这个 Agent。对象是 [准确名称和入口]，
任务场景是 [场景]。我可以提供实际输入输出、操作记录和公开材料。
请交付逻辑流程图、运行机制、上下文与状态、Tool 清单和定义、
完整提示词反推草案及可借鉴点，并区分实测、公开配置、推断与未知。
```

如果调用环境不支持 `$skill-name` 语法，也可以要求 Agent 完整读取本仓库的 `SKILL.md` 及其引用规范后执行。

## 示例

下面是一个不包含真实产品或个人数据的研究请求：

```text
请拆解一个虚构的“会议纪要整理 Agent”。

已知行为：用户上传一段匿名会议记录；Agent 识别议题和行动项；
缺少负责人或日期时请求确认；确认后生成 Markdown 纪要；用户可以要求局部修改。

请仅依据这些材料分析，未知的工具名和内部状态不要写成事实。
```

预期报告会覆盖正常路径、信息不足与局部修改分支，并给出相互一致的上下文约定、工具定义和提示词草案。这个示例只说明输入方式，不代表已经完成真实案例试跑或验证了效果。

## 与竞品拆解 Skill 的关系

本 Skill 可以独立使用，也可配合已公开的 [single-competitor-analysis](https://github.com/BMBWaveforms/single-competitor-analysis)。后者先完成产品层研究，在需要深挖某个 Agent 时调用本 Skill，将六组产物纳入技术层分析。

两个 Skill 分别维护。当前链接已核对，组合调用的端到端效果与跨客户端兼容性仍需验证。

## 限制

- 结果质量依赖真实输入输出、操作记录、截图或可靠公开材料。
- 不应诱导产品泄露内部提示词，也不应探测未授权接口。
- Tool 定义和提示词反推稿通常是研究草案，不等同于被分析产品的实际实现。
- 无法访问产品时只能做材料复盘，并需要明确披露限制。
- 未经实现和测试，不应声称架构已还原、草案可运行或改进有效。
