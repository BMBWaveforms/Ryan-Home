关于银河漫游 AI Interactive Cinema

如果角色换一种回答，故事会不会不同？《银河漫游》把 AI 漫剧与游戏交互结合，让观看故事的人，也能参与其中。

我们用《第零次》承载这个想法：一节异常的车厢、几位带着秘密的乘客，以及等待你回应的时刻。玩家可以作出选择，也可以从某一幕开始改写。

走进故事，再改写它 Play / Create

约 30 秒的开场后，选择出现在人物和空间附近。回应谁、调查什么，会将玩家带入不同影片；随身记录与共享倒计时连接这些场景。

想改写时，从当前幕创建独立草稿，用节点组织角色、对白、HUD 与分支，也可以请 Agent 协助，再回到播放器试玩。当前演示有九幕节点、五段剧情影片，其余四幕保留为内容预览。

职责细节与团队协作

产品定义围绕玩家与创作者两条路径展开，也要划清原型先做什么、哪些能力留到后续。我参与设计提示词与上下文的组织方式，让 Agent 围绕当前幕理解任务，按需读取角色、剧情和素材。

Harness 的产品设计关注工具范围、候选稿和执行记录，约定检查通过后怎样写回草稿，以及作者何时能停止或撤销。前端交互、视觉与 HUD 则围绕叙事节奏安排，对话时把空间留给人物，行动时再突出入口。

表单、画布与播放器共用 HUD 配置，平台主题与游戏内界面分开管理。黄佳家负责整体框架与 Agent 搭建，并担任路演主讲；郭禹擎负责内容编创和视频生成。我们把各自的工作接成了现场可以体验的原型。

产品判断与取舍 Designing AI collaboration

让 AI 参与创作，首先要约定好它理解什么、能改什么，以及一次修改怎样结束。我们先把任务收在当前幕，围绕创作者的一次改稿来安排它的工作。

提示词怎样约定好协作方式？

我们把场景 Agent「小光」定位为创作搭档。提示词先说明它服务于哪一幕、可以修改哪些内容，再约定工作步骤。动手前读取当前状态，引用角色和素材时先查已有资料，完成后校验并说明实际改动。

这样一次模糊的创作意图，就有了可以检查的完成标准。故事文本和角色设定作为创作资料读取，工具权限由产品单独限定，避免素材里的文字改变 Agent 的工作范围。

当前选择 / 先让一次幕内改稿可靠完成，跨幕新建与发布仍由创作者发起。

上下文怎样围绕这一幕组织？

每部作品的每一幕保留独立对话。每轮任务带上当前幕与作品版本，补入有限的近期对话，帮助小光接着理解作者的意图。旧聊天用于延续讨论，真正动手时仍要重新读取作品的当前状态。

需要细节时，再按剧情、角色或出口等分区读取；素材先搜目录，再打开被引用的那一项。作者切到另一幕时，讨论也跟着切换，减少不同场景的内容混在一起。

当前选择 / 按需读取与场景隔离先行，长期世界设定和跨幕记忆还需要继续设计。

Agent 怎样真正参与改稿？

原型先用一个专注当前幕的小光，给它八个创作工具。它可以了解作品，查找角色与素材，在候选稿里修改对白和互动内容，再检查场景、运行基础逻辑预览。工具出错时，会把问题返回给它继续修正。

工具主要围绕本幕开放，作品数值与成长规则是单独允许的范围。小光会说明改了什么，创作者可以查看过程和修改明细，接着进入播放器试玩。画面是否合适、人物表达是否成立，仍由人来判断。

当前选择 / AI 协助把想法落进可编辑的作品，创作者继续掌握创作方向。

Harness 怎样管理一次改稿？

我们把 Harness 理解为围绕 Agent 的整套工作流程。它组织任务说明与上下文，限定工具范围，并记录执行过程。AI 先在独立候选稿里尝试，错误会反馈给它；基础检查通过以后，还要确认作品没有被手动改成另一个版本。

当前原型在这些检查通过后自动写回草稿，整轮修改可以一次撤销。执行中可以停止，失败或冲突时保留已有候选内容和记录。作者能知道这次做到了哪一步，也能继续判断该保留什么。

当前选择 / 先做到过程可查看、失败可停、整轮可撤销，更细的改动确认与差异合并留待后续完善。

下一步，怎样通过节点控制故事修改？

目前节点能组织幕与出口，改写会保留原作来源，草稿与发布版本各自独立。下一步，我希望节点还能说明哪些设定必须保留，以及改动会影响哪些后续情节。创作者先看清影响，再决定只改这一幕、另开分支，还是联动后续节点。

比如后续情节需要一把钥匙，删掉当前幕获得钥匙的内容时，就应该提示依赖它的节点，交给作者决定怎么处理。人设锁定、故事依赖检查和修改范围确认，是我希望继续验证的产品方向。

后续设想 / 当前校验主要检查结构与运行逻辑，故事语义的连贯性仍需作者判断。

这些选择围绕现有原型的场景编辑展开。影片由团队制作后接入，实时生成后续影片仍是后续方向。我们先让作者能完成一幕的修改，再逐步扩大 AI 可以参与的范围。
